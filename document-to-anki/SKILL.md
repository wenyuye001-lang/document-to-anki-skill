# Document to Anki：文档 → 高质量 Anki 卡片

## 何时调用
用户上传 PDF、Word、扫描件、复习讲义、笔记或题库，要求整理为 Anki 卡片，适用于各类课程和资格考试，尤其是需要背诵的简答题、名词解释、比较题和论述题。

## 目标及不可妥协的原则
最终交付物必须兼顾 **忠实原文、清晰的回忆目标、关键词分层、可作答的完整答案、可导入的卡片文件**。

1. **原文优先**：保留原资料术语、学说与答题范围；摘要或改写须能追溯原文。未经授权不得用一般知识悄悄“纠正”考试材料。确需补充时与原文答案分栏，并明确标记。
2. **先校对，再制卡**：扫描 OCR 的换行/相邻标题并不一定是真正的题目边界；不得机械地按自然段或标点切卡。
3. **一个明确回忆目标对应一张卡**：总框架卡考结构，分论点卡考独立要点，整题论述卡考完整输出；不能只把长答案截成“第 N 段：尝试复述”。
4. **关键词不是答案替代品**：每个一级词对应可完整展开的二级要点与三级考场表述。不得为凑卡数丢掉关键限定、例外或原文完整答案。
5. **文件生成 ≠ 导入成功 ≠ 翻面正常**：分别报告静态校验、实际导入、正面/背面验证状态。没有真实测试时不得声称“已验证可用”。
6. **保护既有复习记录**：重复导入前提醒先备份/测试，稳定笔记标识；不要擅自删除或覆盖已有牌组。

## 默认输出方案
- 主要格式：**`.apkg` 完整牌组**，包含牌组、笔记类型、字段、正背面模板和 CSS，减少手机端自行配置错误。
- 备用格式：**UTF-8 `.csv`**，导出清楚的 `Front / Back / Tags` 字段，附导入映射说明；不依赖不确定的头部元数据。
- 报告：`原题覆盖及校对清单.md`、`导入与验收说明.md`。需要时提供源材料对应页码或题目索引。
- 字段优先采用**简单且可靠的 `Front`、`Back` 两字段笔记类型**，来源、框架、分点、页码等可嵌入 HTML；需要更复杂字段时，必须同步生成和验证模板映射。

## 标准流程（必须按顺序执行）

### 1. 原材料盘点
1. 统计文件数、页数、章节、题目数量；区分文本型 PDF、扫描 PDF、Word、图片、表格及特殊符号。
2. 文本型资料优先抽取文字；扫描件先查看页图并进行 OCR，疑难处逐题回看原图。
3. 建立 `SourceIndex`：原题 ID、标题、类型、页码、原文位置、子题及识别/校对状态。
4. 标明页数缺失、重复、模糊、表格读取失败、OCR 置信不足等异常；不可默默跳过。

### 2. 逐题修复与校勘
1. 按标题与语义确定每题真实起止范围；原文每题单独对应一条来源记录。
2. 纠正可明确证实的 OCR 错字、断行、编号错序；仍不确定的内容标 `待人工核对` 和具体页码。
3. 专门排查**跨题串入**：一个主题的答案中突然出现另一主题的标题、定义或学说时必须回看页图。
4. 建立核对表：`原题 → L1 关键词 → L2 分论点 → L3 原文完整答案 → 卡片 ID`。
5. 比对源题索引与输出：所有原题都要有状态（已制卡 / 因故排除并说明 / 待核对）。

### 3. 形成背诵层级
对每一道题保留三个层次，必须明确原文与 AI 归纳的区别：

- **L1 一级关键词（提纲）**：通常 2–7 个简短、平行的实义词组，顺序符合原文逻辑。可给出便于联想的简短记忆线索，但不能改写原意。
- **L2 二级分论点（结构）**：逐条描述每个关键词对应的概念、条件、区别标准、必要限定、例外等；使用编号与短段落。
- **L3 完整答案（考试输出）**：与源材料一致、可以直接练习复述或书写的连续答案；严格保留专业术语。

对定义题突出“主体—条件—行为—后果”；对比较题突出共同维度；对条件或要素类题目突出层次和逻辑；对论述题保留整体顺序和衔接。

### 4. 设计卡片（不要机械拆分）
优先设计：

- **总框架卡**：正面为原题 + “列出结构与关键词”；背面为有序 L1 关键词、论点顺序和简短框架逻辑。
- **独立分论点卡**：正面明确“原题的第 X 个论点是什么 / 如何阐述”，可显示论点名称但不泄漏待答内容；背面给 L2 和对应 L3 片段。
- **综合论述卡**（可选）：正面为整道原题；背面为全部 L1/L2/L3，考前模拟书写使用，可另组或加标签，以减少日常复习过载。

每卡需要 `stable_id`、`source_id`、`page`、`card_type`、`qa_status`、`topic`；用稳定 GUID 或相应笔记标识辅助日后更新。若将这些元数据放入标签/隐藏区域，也要保证可追溯。

### 5. 卡面排版（手机优先）
- 正面：明确题目、题型、当前回忆任务；**不提前完整呈现答案**。
- 背面：先展示 L1 关键词，再按编号展示 L2 展开，最后展示 L3 原文答案（或该分论点的完整作答），下方标出处与校对状态。
- 统一标题、编号、关键词标签、定义与例外的视觉层次；正文保持可读字号与舒适行距，控制每行长度，适配窄屏。
- 保证暗色模式对比度；不用远程字体、外链脚本或依赖联网的交互效果；颜色不能是唯一线索。
- HTML 必须结构完整；不要写可能掩藏答案的 CSS。

### 6. 生成 APKG（优先沿用已成功的结构原则）
**首选可靠的 Anki 库或 Anki 官方接口生成**。如果不得不直接制作旧式数据库封装，必须掌握当前导入器所需 schema，不能只拼出能解压的 ZIP。

本 Skill 有**用户确认成功的案例**（详见 `references/verified-success-case.md`）：最后的修正版 APKG 含 `collection.anki2`、`media`，notes 与 cards 数量一致，字段 `Front` 和 `Back`；正反面模板分别包含 `{{Front}}` 和 `{{Back}}`。其 `col.decks` 包含有效牌组与默认牌组，并补齐所需配置及每日统计字段。用户已确认**导入成功、翻面能看到答案**。

可复用的模板示例（字段必须匹配）：

```html
<!-- 正面 -->
<div class="frontside">{{Front}}</div>

<!-- 背面 -->
<div class="frontside">{{Front}}</div>
<hr id="answer">
<div class="backside">{{Back}}</div>
```

**注意**：成功案例说明这套结构在当时用户的 Anki 环境中可用，不意味着所有 Anki 版本都必须使用旧版 `collection.anki2`。不要照抄示例数据库的时间戳、牌组 ID、笔记 ID、用户数据或版本字段。优先由兼容的库/官方 API 自动填充。

### 7. 生成 CSV（备用方案）
1. 用正确的 CSV 解析/写入库生成 UTF-8 文件，正确转义双引号、换行、逗号和 HTML 内容。
2. 推荐数据列 `Front,Back,Tags`，**如不确定 Anki 头指令的处理方式，不写 `#columns` / `#separator` 这样的元数据行**，并在使用说明中注明顺序。
3. 如果有表头，需要在导入时明确“跳过首行”，或直接输出无表头数据；不能让表头变成学习卡。
4. 导入时核实字段映射、HTML 选项与使用的笔记类型。CSV 的 Back 列有值不代表卡片模板一定展示它。

### 8. 分三级验证，不可混同
**A. 静态检查（AI 可执行）**
- 正面和背面不能为空；字段名与正反面模板引用一致；样式不隐藏答案。
- 题目索引覆盖完整、无错误合并、异常长卡及明显重复；关键词与分论点一一对应。
- CSV 内容可以被重新解析；元数据行没有混入第一张卡。
- APKG 可解压；SQLite `PRAGMA integrity_check` 成功；`col` 内 JSON 能解析，`decks/models/dconf` 与 `notes/cards` 关系一致；检查必要的牌组配置字段。
- 可以使用 `scripts/verify_apkg.py` 检查旧式 `collection.anki2` APKG 的基本结构；**该脚本不是 Anki 导入测试**。

**B. 软件导入（需要实际 Anki 环境）**
- 在隔离的测试用户配置文件/测试牌组中导入 APKG，确认无错误、数量正确、字段映射正确。
- 有条件时分别验证 Anki 桌面和 AnkiMobile；若只验证一种客户端，明确说明设备与版本的限制。

**C. 正反面实测（通过才可称完整成功）**
- 抽取首张、长答案题、含特殊字符题、框架卡与分论点卡，逐张检查正面、点击显示答案后的背面、滚动显示、暗色模式和手机宽度。
- 用户明确反馈“导入成功、答案正常显示”，可以记录为该**具体交付包在用户环境的成功验证**；不外推为未来所有 APKG 均兼容。

状态表述必须精确：`已生成` / `静态检查通过` / `实际导入通过` / `正反面显示通过`。见 `references/acceptance-checklist.md`。

### 9. 最终交付
提供：① APKG ② CSV 备用 ③ 原题覆盖与校对报告 ④ 导入/验收说明；按需打 ZIP。

报告写明：原题总数、三类卡数、覆盖率、未校对/待核对题目、QA 范围、**实际验证到哪一级**。如没有真实导入环境，明确请用户对一份独立牌组进行最终导入和翻面检查。引导先备份，切勿贸然清空原有复习数据。

## 常见失败及禁止重犯
1. **`#columns:ID,Front,Back,Tags` 显示在正面**：元数据误作正文；重新处理 CSV 头部与字段映射。
2. **正面正常、背面空白**：检查 Back 值、字段对应、背面模板和 CSS；`{{Back}}` 不可缺。
3. **`500: JsonError { info: "decoding decks: JsonError" }`**：APKG 中 `decks` JSON 结构可能不完整；应使用正确打包工具和真实导入测试。2026-10 的一次修正版补齐相关牌组配置后，用户确认成功，但并不能断言单一字段就是唯一根因。
4. **串题和 OCR 错误**：先对照原图校对，再拆分。
5. **片段卡过多**：语义拆分、减少重复，不机械按句子或段落切分。

更详细的案例与排查见 `references/troubleshooting.md`、`references/verified-success-case.md`。

## 最终完成标准
**资料内容可溯源、题目没有误合并、背诵层级真正可用、完整答题表述不丢失、APKG/CSV 技术检查结果真实、实际导入与翻面验证范围陈述准确。**
